매체에서 업무 자동화라는 걸 자주 접하고, LLM 활용 일상 루틴 자동화를 보고 막연하게 내 일상에서도 생산성을 향상시키는 궁극의 자동화 프로세스를 만들고 싶다는 생각만 했음

그러다 영상 제작 프로그램 개발해서 수익화했다는 컨텐츠를 접하고, '개발'이 의미하는 액션과 결과물이 궁금했음 (프론트로 따지면 리액트로 개발환경 구축하고, 컴포넌트 작성해서 웹앱으로 띄움. 영상제작 프로그램은 어떻게, 무엇을 만든 건지 모호했음)

여러가지 좀 찾아본 결과, 별도 UI없이 클로드 코드를 클라이언트로 해서, llm 워크플로우를 구축한 걸로 이해했음 (일반인 대상이라 프로그램 개발이라는 용어를 사용한 것 같음)

'개발'의 의미 찾기 탐구 과정
1. 스킬 문서 작성인지, 다른 방법 뭐가 있는지 찾아보기
-> 의도한 결과물을 만드는데 필요한 모든 것을 칭하는 걸로 이해함
- 전체 워크플로우 구축
- 각 단계에 필요한 것들 개발 (새로 작성하거나 연결)
   - mcp 연결 및 스크립트 개발 (툴)
   - 자료 검색 (RAG?)
   - db, local file 연결 (데이터)
   - 보다 구체적인 예시들: https://fastcampus.co.kr/biz_online_claudeauto 
2. 여전히 안와닿아서 프로젝트 구조 & 클라이언트 형태 찾아보기(프론트엔드 프로젝트와 비교)
-> 요청 엔트리 포인트가 되는 클라이언트는 필요에 따라 달라지는 걸로 이해함
- 클로드 코드로 요청 -> 스킬 읽기 -> 정의한대로 동작 -> ..
- 시작 스크립트 실행(파이썬, 노드 등) -> 정의한대로 동작 -> ..
- UI 입힌 앱으로 빌드
3. 구체적으로 어떤 식으로 작성하는건지 궁금해서 세부 프로세스 동작 생각해보기
-> 마찬가지로 필요에 따라 달라지는 걸로 이해함
- 스킬 파일 작성 (이것도 잘 모르겠지만 워크플로우 정의한대로 실행하게끔 llm이랑 같이 작성할 듯)
- llm 기반 시스템 구축
   - 워크플로우 패턴 활용해서 llm 호출부 개발 (이걸 이해하는데 있어서 찾아본 자료는 별도 개념 설명글로 작성해서 링크하자)
   - 에이전트 구축 (이것도 구체적인건 잘 모르겠음)

계속 좀 와닿지 않았던 건 워크플로우 패턴이든, 에이전트든 일반 사용자로서 데스크탑 앱 자체가 에이전튼데 이걸 써서 뭘한다는거지가 파악이 안돼서 계속 맴돌았음

llm 앱과 단일 소통을 하는 일반적인 사용법으로도 쓸 수 있지만, LLM 기반 시스템을 구현해 특정 형식의 결과물을 특정 이상의 품질로 만들기 위한 방법을 소개하는 맥락으로 멘탈모델 전환이 필요했음

이제 이해한 바에 따르면 - 얼마나 사람의 개입없이 처리하게 할것이냐에 따라 미리 구축해놓는 범위가 달라짐
   데스크탑 앱 사용 → 앱 내 시스템 프롬프트 설정 기능(claude project, gemini gems, chatgpt GPTs) → LLM 기반 시스템 구축 (일반 요청 응답 → 워크플로우 패턴 적용 → 에이전트)
   => 패턴 적용부터 에이전트까지가 따로 링크한 글이 다루는 범위


이런것들을 보다보니 ai를 다루는 건 사람이 일을 잘하기 위한 패턴을 잘 알아야하고, 결국 일 잘하는 사람이 ai를 잘 쓰겠구나라는 생각이 듦

이글을 보고 좋은 점은 일 못하는 사람도 잘할 수 있겠구나라는 생각, 안좋은 점은 이렇게 필요에 따라 패턴화가 되다보면 이 끝에는 인간의 판단이 아예 필요없어지겠구나 라는 생각이 들었음

그러면 그 시점에 업무에 있어서 인간이 할 수 있는게 뭐가 남아있을까 하는 생각과 지금 시점에 업무 자동화 등을 하고 ai 리터러시를 키워야겠다는 생각이 들었음
